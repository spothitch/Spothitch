## Améliorations possibles (non implémentées)

### Priorité haute (impact utilisateur direct)
1. **Firebase Auth en local** : Erreur "invalid-api-key" en dev (normal sans .env.local, mais visible dans Fox). Vérifier que ça n'affecte pas les utilisateurs en production.
2. **149 handlers lazy non chargés** : Fox Layer 5 perd 10 points à cause de handlers qui ne sont jamais chargés (features beta gardées). Normal pour l'alpha, mais à monitorer.
3. **FAQ** : Créer un vrai contenu FAQ pour la beta (featureId dédié dans featuresData.js)
4. **Notifications push** : Créer une fenêtre Coming Soon dédiée (pas réutiliser celle de proximité)
5. **Changelog "Quoi de neuf"** : Créer un vrai écran avec les mises à jour récentes
6. **Pages sociales** : Créer les comptes Instagram/TikTok/Discord avant de remettre les liens

### Priorité moyenne (qualité/UX)
7. **Mini-carte : fallback quand la carte principale n'est pas visible** : Si l'utilisateur ouvre AddSpot sans avoir chargé la carte (ex: depuis un lien partagé), le snapshot échoue et tombe sur le fallback MapLibre (lent). Solution : pré-charger un snapshot statique.
8. **Autocomplete : pré-remplir quand l'utilisateur revient** : Si l'utilisateur fait retour puis revient à l'étape 1, la ville de départ est dans le champ mais l'autocomplete n'a pas de `selectedItem` → marqué invalide au blur.
9. **Quality Gate warnings (34)** : Principalement des exports morts et des clés localStorage non critiques. Aucun ne bloque.
10. **Share handler** : Fox signale "No share handler found on window" — le share target fonctionne mais le handler n'est pas exposé globalement.
11. **SpotDetail close guard** : 600ms est un compromis. Si un utilisateur clique très vite pour fermer, il devra attendre 600ms. Surveiller les retours.

### Priorité basse (technique/dette)
12. **`openFAQ = guard('score-confiance')`** : Mauvais mapping dans beta guards. À corriger quand FAQ sera prête.
13. **`openChangelog` fait `showFAQ: true`** : Redirige vers FAQ au lieu d'un changelog. À séparer.
14. **Lien profil social utilisateur** : Instagram/TikTok/Facebook dans le profil utilisateur pointe vers des URLs vides si pas rempli.
15. **Cookie banner** : Apparaît sur le profil (visible dans le screenshot audit). Vérifier qu'il ne bloque pas les interactions.

## Recommandations Performance

### Bundle (analyse build)
| Chunk | Taille gzip | Note |
|-------|-------------|------|
| MapLibre GL JS | 269 KB | Incompressible, chargé au démarrage |
| Firebase (Auth+Firestore) | 159 KB | Chargé lazy après auth |
| Index (app) | 90 KB | OK |
| Fichiers langue (FR/EN/ES/DE) | ~50 KB chacun | Vérifier qu'un seul est chargé à la fois |
| Gamification | 176 KB | 100% beta, pourrait être lazy-loadé plus tard |
| MapLibre CSS | 69 KB | Chargé même quand pas sur l'onglet carte |

### CRITIQUE (impact immédiat)
1. **innerHTML reconstruit TOUT le DOM à chaque changement d'onglet** (main.js:802). Cause des reloads/scintillements visibles. Solution : cacher/montrer les panneaux avec display:none au lieu de tout détruire/recréer.
2. **mousemove listener global sans throttle** (main.js:2186). Le bouton feedback écoute TOUS les mouvements de souris/doigt sur la page. 50-100 événements/seconde. Consomme CPU et batterie.
3. **Dépendance circulaire social ↔ gamification**. Empêche le code splitting, force ~100 KB supplémentaires dans le bundle principal.

### HAUT (performance dégradée)
4. **setInterval sans cleanup** : network.js (30s), quiz.js (1s), nearbyFriends.js, companion.js, autoOfflineSync.js. Fuites mémoire, timers qui s'accumulent.
5. **spotLoader reconstruit un tableau géant** : `[...allLoadedSpots, ...newSpots]` copie 100K éléments à chaque pays. Utiliser push() ou Map.
6. **10 modules importés statique ET dynamique** : mapMarkers.js, pwa.js, idb.js, etc. Empêche le code splitting.
7. **Fichiers langue 190 KB chacun** (60 KB gzip). Diviser en sections (core, profile, addspot, social).
8. **Index.js 320 KB** (92 KB gzip). Extraire les handlers non-critiques au démarrage.

### MOYEN (améliorations UX)
9. **MapLibre CSS** : chargé globalement (69 KB) même quand pas sur l'onglet carte.
10. **getState() copie à chaque appel** : `return { ...state }` crée un objet à chaque lecture.
11. **Pas de WebP/AVIF pour les images**. Conversion côté serveur réduirait ~50% la taille.
12. **SW CacheFirst 7 jours pour spots** : les utilisateurs voient des données périmées pendant 7 jours. Réduire à 24h ou passer à NetworkFirst.
13. **Pré-chargement spots** : charger le pays de l'utilisateur pendant le splash (GPS/timezone).
14. **Cache tuiles Service Worker** : déjà CacheFirst 1 an, 500K entrées. OK.
15. **Images spots** : lazy-loading partiel (IntersectionObserver OK, mais 16 endroits assignent .src directement).
16. **skipWaiting: true** force le nouveau SW, risque de casser l'app en cours d'utilisation.
17. **95 lazy loaders sans priorisation** : précharger les 5 plus utilisés (Auth, AddSpot, SpotDetail, SOS, Profile).
18. **Gamification chunk** (56 KB gzip) : 100% beta, déjà lazy et dans globIgnores du SW. OK.
19. **Social non splitté** : 148 KB en 2 chunks. Lazy-loader les sous-onglets individuellement.
20. **Quiz timer s'accumule** : ouvrir/fermer le quiz 10 fois = 10 intervals actifs.
